# Repository Guidelines

## Project Structure

AutoVerse is a static-first React/TypeScript app. Pages are in `src/pages/`, shared UI in `src/components/`, simulations in `src/features/`, state in `src/stores/`, and shared logic in `src/lib/`. Lessons are JSON under `src/content/topics/<category>/`; public models and icons are in `public/`. Tooling lives in `scripts/`, architecture notes in `docs/`, and GitHub Pages deployment in `.github/workflows/`.

## Build, Test, and Development

- `npm run dev` starts Vite locally; `npm run preview` serves the production build.
- `npm run build` type-checks, bundles, and prerenders `dist/`.
- `PUBLIC_BASE_PATH=/AutoVerse/ SITE_URL=https://maxrecursion.github.io/AutoVerse npm run build` builds for GitHub Pages.
- `npm run typecheck` and `npm run lint` check TypeScript and ESLint.
- `npm test` runs Vitest; `npm run test:e2e` runs Playwright specs when present.
- `npm run validate:content -- --strict` validates lesson schemas and cross-references.
- `npm run og:images` redraws the share images in `public/og/` after adding pages or changing titles and descriptions; commit them (a test fails when they are out of date).

## Style and Naming

Use strict TypeScript and two-space indentation. Components use PascalCase (`TopicCard.tsx`); utilities and hooks use camelCase (`useMediaQuery.ts`); content files use lowercase kebab-case. Import app code through `@/`. Keep simulation math pure and follow nearby patterns. ESLint checks hooks and unused variables.

## Testing

Place unit and component specs beside the code as `*.test.ts` or `*.test.tsx`; scripts use `*.test.ts`. No coverage threshold is configured. For lesson-data changes, run strict content validation and relevant tests. Use `tests/e2e/` for full navigation or interaction flows.

## Commits and Pull Requests

Use short, imperative commit subjects (for example, `Add transmission lesson`). Work directly on `main`; never create alternate branches or pull requests. After changes are validated, commit to `main` and push immediately.

## GitHub Pages

`.github/workflows/deploy-pages.yml` deploys `dist/` on pushes to `main`. Keep `PUBLIC_BASE_PATH` and `SITE_URL` aligned with `/AutoVerse/` so assets, router links, prerendered links, and canonical URLs work at the repository subpath. Optional repository variables `GOOGLE_SITE_VERIFICATION`, `BING_SITE_VERIFICATION` and `INDEXNOW_KEY` turn on search-console verification tags and IndexNow pings (see `docs/SEO.md`).

## Search and Static Rendering

Every public page is rendered to HTML at build time from `src/app/routes.tsx` (`src/entry-server.tsx`, `scripts/prerender/`). Components must not touch `window`, `document` or `localStorage` during render, and collapsed content stays in the DOM with `hidden`. Browser tests wait for `html[data-app="ready"]` before clicking. Every lesson needs `seo` (title up to 60 characters, description 70–160, both unique), three or four `faq` entries in original wording that the lesson supports, and `about` (Wikipedia article URLs checked to exist). New pages also need metadata in `scripts/prerender/routes.ts` and `npm run og:images`. Details in `docs/ARCHITECTURE.md` and `docs/SEO.md`.

## Content and Learning Flow

Keep topic JSON aligned with `src/lib/schemas.ts`. Write original educational text and retain accurate source and licensing metadata. User progress stays in this browser; do not add secrets or runtime credentials. Maintain `docs/learning-experience-plan.md` as shared product guidance. Resolve the active path from recent lessons via `features/progress/paths.ts`; reuse `PathAction` so home and progress show the same start, continue, and completion states. Lesson pages should show route position and the matching next step. Every lesson sets `layer` (`surface | mechanism | engineering`); `features/progress/curriculum.ts` (`resolveNextUp`) is the one source for "what next?" — do not compute a next lesson anywhere else. Lesson stage progress is derived from evidence in `useProgress().lessons` (`features/progress/stages.ts`); never mark a stage done on the learner's behalf. Engineering history lives in `src/content/pioneers.json`, generated by `scripts/content/build-pioneers.py`: each entry needs a person/team, year, headline, an original-wording story, linked lessons (and parts when well established) and at least one source that was actually fetched and read, with the date. Leave out any claim the source does not state; distinguish invention, patent and production milestones; use `caution` for shared or contested credit and doubtful legends; avoid sole-inventor claims.

The product tour (`src/features/tour/`) points at `data-tour="…"` anchors; if you move or remove one, update `steps.ts` (a test checks every anchor exists). Anything that records progress on its own (page visits, "read" evidence, passive mission ticks) must stay silent while `isTourActive()` from `@/lib/tourState` is true. Certificates (`src/features/certificate/`) require every lesson in a course completed and every quiz taken; call `checkCertificates()` after anything that can complete a lesson or quiz. Browser tests live in `tests/e2e/` and run against the production build (`npm run test:e2e`).
